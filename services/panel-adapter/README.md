# panel-adapter（适配服务）：什么时候需要它、什么时候不需要它

> 先写清楚再写代码（DEV-PLAN §3.6）。本阶段（阶段 0）只有这份说明，
> 没有代码——原因见 docs/interface-audit.md：面板 1.3.29 里没有
> agent 能用的用户表下发接口，也没有流量接收接口，adapter 现在
> 没有东西可翻译。先把结论写死，不要先写一套对着不存在的接口的代码。

## 是什么

一个 Go 小服务，跑在面板机上（或 agent 与面板之间），只做一件事：
把 agent 的 push 翻译成面板现有接口能接的形状（字段名、去重键、
汇总口径）。它本身不存用户数据、不做决策，面板还是唯一的决策方。

## 什么时候需要它

- 面板加了三个新接口（D10 拍板后）之后：面板的接口字段名与 agent
  的推送形状不一致时，在这里翻译，不改面板、不改 agent。
- 面板版本升级、字段改名时：只改 adapter，agent 不用跟着升级。

## 什么时候不需要它

- 面板的三个新接口字段名与 agent 的推送形状本来就一致：agent
  直连面板，不用中间再过一道。
- D10 没拍板之前：没有新接口，adapter 没有东西可翻译，
  写了也是摆设——这就是阶段 0 不写它代码的原因。

## 做不到的事（不要对它有不切实际的期望）

- **不能代替 D10。** 面板现有接口里没有一个是“写用量”的
  （`central/user-traffic` 只读，`central/user-forwards` 写的是转发
  不是用量）。adapter 不能凭空变出一个写用量的接口。
- **不能直接改面板的 `user_traffic.json` 文件。** 面板的用量存在
  内存 map 里，文件只是落盘；adapter 直接改文件会被面板下一次
  保存覆盖掉，增量丢了还不报错（见 docs/interface-audit.md §4）。
